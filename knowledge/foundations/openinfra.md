**Stance: permitted, and since 2026-09-25 explicitly welcomed.** OpenInfra's *Policy for AI Generated
Content* covers *"All contributions of content committed into source revision control systems by
projects housed under the OpenInfra Foundation."*[^openinfra-ai-policy] Version 0.12.0 opens with
five principles, the first being *"AI use is welcomed."*[^openinfra-ai-policy]

## What it asks now

- **A human answers for every contribution.** *"Purely autonomous submissions with no identifiable
  accountable human are not acceptable, not because a tool was used, but because there is no
  accountable party to maintain the work or follow up on issues."* Documented automated processes,
  such as release tooling, remain allowed when people take responsibility for them.[^openinfra-ai-policy]
- **Material use is labelled.** *"When AI tools materially shape a contribution, that fact is recorded
  in the commit metadata using a machine-readable label"*.[^openinfra-ai-policy]
- **One label is recommended and the other is still allowed.** *"We recommend using “Assisted-By”
  moving forward, though “Generated-By” is still approved in this policy, and may be found in the
  commit history of some OpenInfra projects."*[^openinfra-ai-policy] The label comes with an
  explanation of *"how much of the change came from the tool."*[^openinfra-ai-policy]
- **The tool must not claim the output.** *"Make sure the AI tool doesn’t claim proprietary rights to
  the code or content generated by the tool."*[^openinfra-ai-policy]
- **No different bar in review.** *"Reviewers may reject low-quality work, but neither a higher nor a
  lower bar applies because a tool was involved."* The reviewer checklist adds: *"The disclosure label
  is not grounds for rejection; it is context."*[^openinfra-ai-policy]

The policy names `Co-Authored-By` alongside `Signed-Off-By` as *"a statement that a human contributor
takes responsibility for the entire contents of the commit"*.[^openinfra-ai-policy] It does not say
whether a `Co-Authored-By` line naming a model counts as that statement.

## Version 0.12.0 reversed two positions

This record was first written on 2026-08-05 against an earlier version. The archived copy of
2026-08-27 is version 0.11.2,[^openinfra-ai-policy-0112] and the change history dates 0.12.0 to
2026-09-25: *"Revised content based upon OpenInfra AI Policy Working Group discussions and Governing
Board review"*.[^openinfra-ai-policy]

| | Version 0.11.2 | Version 0.12.0 |
|---|---|---|
| **Labels** | `Assisted-By` for assistive or predictive tools; `Generated-By` when *"a substantial portion of a patch is generated"*, with generative tools permitted *"under limited circumstances"*[^openinfra-ai-policy-0112] | `Assisted-By` recommended for all material use; `Generated-By` *"still approved"*[^openinfra-ai-policy] |
| **Reviewers** | *"Reviewers should apply heightened scrutiny to AI-generated content."*[^openinfra-ai-policy-0112] | *"Hold AI-assisted contributions to the same standard as any other contribution."*[^openinfra-ai-policy] |
| **Trust** | *"Treat such code as if it came from an untrusted source."*[^openinfra-ai-policy-0112] | *"Don’t trust AI output implicitly."*[^openinfra-ai-policy] |

**The split this record called the most precise labelling scheme in the bundle is gone.** Version
0.11.2 told contributors to pick the label by what the tool did. Version 0.12.0 explains the move to one
label as recognising *"that AI tools assist developers in many different ways"*.[^openinfra-ai-policy]
The reviewer clause, which this record called rare because it placed a burden on reviewers as well as
submitters, has reversed: a label now changes nothing about the review.

## The label can still come off

Both versions let a reviewer drop the label after rework. Version 0.12.0: *"If the change set is
substantially re-worked by human changes during the code review process, consider whether it makes
sense to remove the “Generated-By” or “Assisted-By” label prior to committing."*[^openinfra-ai-policy]
Everywhere else in this bundle a label records how a patch came to exist. Here it can describe what is
about to be merged instead, and those two readings are incompatible.

## What a contributor must do

Sign off as usual. If AI tools materially shaped the change, add `Assisted-By:` to the commit message
and explain how much came from the tool. Do not use a tool that claims rights over its output. Expect
the same review as any other change.
