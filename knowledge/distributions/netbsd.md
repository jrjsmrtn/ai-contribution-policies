**Stance: restricted, with a named approval route.** The commit guidelines state that *"code
generated by a large language model or similar technology, such as GitHub/Microsoft's Copilot,
OpenAI's ChatGPT, or Facebook/Meta's Code Llama, is presumed to be tainted code, and must not be
committed without prior written approval by core."*[^netbsd-commit-guidelines]

## What it covers

The rule sits inside a wider clause on **code provenance** — the surrounding text concerns
verifying that an author is the sole author and did not copy other code, and forbids committing
from foreign trees. AI output is treated as one case of unclear provenance rather than as a
separate subject.

## The mechanism is a presumption, not a prohibition

The wording is precise and worth not paraphrasing: the code is *presumed tainted*, and the bar is
on committing it **without prior written approval by core**. That is a rebuttable presumption with
a named decision-maker — materially different from a flat ban, and it means a contributor with a
case has somewhere to take it.

## What a contributor must do

Do not commit LLM-generated code on your own authority. If you believe a case exists, obtain
**written** approval from core first.

## Re-verification notes

This lives in the developer commit guidelines rather than a standalone policy page, so it can
change without an announcement. Re-check the guidelines page itself, and watch for the list of
named tools ageing — it currently names Copilot, ChatGPT and Code Llama.
