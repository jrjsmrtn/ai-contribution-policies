**Stance: two written policies that point in different directions.** `CONTRIBUTING.md` prohibits AI-generated
pull requests; `AI_POLICY.md` welcomes AI for coding. Both are identical on `main` and on the default
branch `v2.0-cyanoptera` (checked 2026-09-16), and **neither file links to the other.**

## The older rule: do not submit AI-generated pull requests

Added on 2025-06-11 as the last section of the contributing guide:[^dd-pr-17882]

> ## Generative AI Policy
>
> **Please do not submit pull requests generated by AI (LLMs).** Reviewing such PRs puts a considerable
> burden on the maintainers.[^dd-contributing]

Two sentences, a prohibition and a reason — reviewer burden, the ground most projects here give.

## The newer rule: AI welcome, with conditions

A year later, a separate file:

> Using AI (i.e., LLMs) as tools for coding is welcome.[^dd-ai-policy]

It keeps a high bar and splits responsibility — *"the project maintainers remain responsible for any
code that is published as part of a release. Contributors are expected to be responsible for any code
they publish"* — and then reserves the conversation to humans:

> **AI should not be used to generate comments when communicating with maintainers and contributors**.
> Comments are expected to be written by humans. Comments that are believed to be written by AI may be
> hidden/closed without notice.
>
> If you are opening a pull request, you are expected to be able to explain the proposed changes in
> your own words. This includes the pull request body and responses to questions. **Do not copy
> responses from the AI when replying to questions from maintainers.**
>
> This project requires a human in the loop who understands the work produced by AI. **Autonomous
> agents are not allowed to be used for contributing to this project**. Pull requests that appear in
> violation of this will be closed, perhaps without notice.[^dd-ai-policy]

Quoted model output must be in a quote block, disclosed, and accompanied by human commentary, and
translation is welcome provided the result *"reflects your own voice and ideas"*.[^dd-ai-policy] See
[prose reserved to humans](../mechanisms/prose-reserved-to-humans.md) and
[human in the loop](../mechanisms/human-in-the-loop.md).

## They were never reconciled

The pull request that added `AI_POLICY.md` describes itself as *"Initial version that captures our
current stance"*.[^dd-pr-23025] That reads as the newer file superseding the older section — but the
older section was not removed or reworded, and the contributing guide does not mention the new file.

**The literal texts conflict on the central case.** A pull request whose code an AI wrote, reviewed and
explained by its human author, is welcome under `AI_POLICY.md` and is a pull request *"generated by AI"*
under `CONTRIBUTING.md`. A contributor who reads only the contributing guide learns only the
prohibition.

**Both were merged the same way.** Each pull request was opened by a different contributor, merged the
same day by the same maintainer account with no review, and closed with a one-word *"Thanks!"*.[^dd-pr-17882]
[^dd-pr-23025] The DuckDB Foundation, a non-profit, holds the project's core intellectual property and
trademarks;[^dd-foundation] nothing in either pull request involves it.

## The newer file is ripgrep's, with four sentences changed

`AI_POLICY.md` ends: *"This policy was adapted from [ripgrep's AI policy], which was adapted from [uv's
AI policy]."*[^dd-ai-policy] **It is the only borrower in this bundle that credits two hops of its
lineage**, Astral → [ripgrep](ripgrep.md) → DuckDB. See [policy by copying](../mechanisms/policy-by-copying.md).

Compared sentence by sentence on 2026-09-16, with headings set aside, ripgrep's text[^dd-ripgrep-policy]
and DuckDB's differ in exactly four places:

| ripgrep | DuckDB |
|---|---|
| *"…when communicating with maintainers."* | *"…when communicating with maintainers **and contributors**."* |
| *"…may be hidden without notice."* | *"…may be **hidden/closed** without notice."* |
| *"Do not share long snippets."* | *"Do not share long snippets: **pasting an interaction with AI in a pull request description is not a substitute for human commentary.**"* |
| *"This policy was adapted from [uv's AI policy]."* | *"…adapted from [ripgrep's AI policy], which was adapted from [uv's AI policy]."* |

DuckDB also added section headings. ripgrep's policy has not changed since 2026-05-26, so the text
DuckDB took on 2026-06-03 is the current one.

**Three details of the copy are worth holding:**

- **The sanction grew.** Astral and ripgrep both only *hide* comments believed to be AI-written; DuckDB
  says they may be *"hidden/closed"*.
- **The pin travelled, the pinning did not.** DuckDB links uv's policy at the exact commit ripgrep
  pinned — copied verbatim from ripgrep's text — but links ripgrep itself at `master`, unpinned.
- **The reason stayed behind.** Astral justifies its human-in-the-loop rule by *"the foundational nature
  of our projects"*; ripgrep dropped that sentence at the first hop, and DuckDB did not restore it.

## Practice: AI co-authorship is routine

A partial clone of both `main` and `v2.0-cyanoptera` on 2026-09-16 counts **141 commits committed since
2026-05-01 with a `Co-Authored-By:` trailer naming `noreply@anthropic.com`** — identical on both branches.

- **Fifteen git author names**, including one commit under `Mytherin` — the account that merged both
  policy files — and two under Hannes Mühleisen, one of the two people the project's FAQ names as its
  creators.[^dd-faq] One author name accounts for 40 commits, all in 2026-09.
- **By author month:** 6 in 2026-04, 27 in 2026-05, 17 in 2026-06, 20 in 2026-07, 29 in 2026-08 and 42
  in 2026-09. The 33 from April and May were authored while the contributing guide's prohibition was the
  only written rule.
- **Ten distinct model strings**, from `Claude Opus 4.6` to `Claude Sonnet 5`; one commit uses
  `Assisted-by:`, and three carry *"Generated with [Claude Code]"*. Neither policy asks for any trailer.

**Measured by clone, not by search.** GitHub's commit search reported 42 such commits for the same
repository; the clone found 141, and a control term returned 25 hits in search against 312 in the clone.

## The agent files say nothing about the policy

`AGENTS.md` is a 17,911-byte codebase guide — build commands, test format, architecture, coding
conventions. It never mentions AI policy, and its only reference to pull requests is that all tests
must pass before one is submitted.[^dd-agents]
`CLAUDE.md` is a regular 10-byte file containing `@AGENTS.md` (mode `100644`). It was the project's
original instruction file; on 2026-06-05 its content moved to `AGENTS.md` and it became an import, with
the contributor explaining the choice: *"avoided symlinking because it complicates things on
Windows."*[^dd-pr-23077] That is the first stated reason in this bundle for preferring an import over a
symlink — see [agent-file pointers](../mechanisms/agent-file-pointers.md).

## What a contributor must do

**Satisfy both files, because both are in the repository.** Use AI as a coding tool if you like, but
be able to explain every change in your own words, write the pull request description and every reply
yourself, quote any model output in a block with your own commentary, and never let an agent contribute
autonomously. Do not submit a pull request whose substance an AI generated: the contributing guide still
says not to, and nothing in the newer file withdraws it. No trailer is required.

## Re-verification notes

**Check whether the two files have been reconciled** — a removed or reworded `CONTRIBUTING.md` section,
or a link to `AI_POLICY.md`, changes this record's central finding. Check both `main` and the default
branch, which is currently named for a release line and may change.

**Count commits from a clone, not from search** — search undercounted by more than two thirds here.
`git clone --filter=blob:none --no-checkout --shallow-since=<date>` is enough to grep trailers.
