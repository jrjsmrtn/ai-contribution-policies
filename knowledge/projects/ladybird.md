**Stance: AI assistance permitted under a quality obligation — and the contribution channel is shut.**
Ladybird's AI rules are unremarkable. What makes it the sharpest case in this bundle is what the
project did next: on **2026-06-05** it stopped accepting public pull requests from anyone outside the
maintainer group, and named AI as the reason.

> Ladybird is developed by a group of project maintainers, who introduce all changes to the codebase.
> **We do not accept pull requests from non-maintainers** and do not allow code change proposals
> through any other route.[^lb-contributing]

## The AI rules, which are mild

> Usage of AI assistance is usually fine, but **you are responsible for making sure the quality of the
> output is up to the standards of the project.** Currently, AI-generated output is often too verbose
> and its quality is subpar compared to carefully written human work.
>
> Do not use an AI or LLM to generate changes, respond to issues, or participate in project discussion
> **without holding the output to the same standards as human-written content.**
>
> Do not use AI-generated descriptions or summaries **as a substitute for understanding** the relevant
> code, issue, or discussion.[^lb-code-policy]

**Nothing is forbidden by origin.** There is no trailer, no disclosure, no ban — only a standard the
output must meet and an obligation to understand what you submit. The third clause is the distinctive
one: it forbids using a summary *instead of* reading, which is an instruction about the contributor's
own comprehension rather than about the artifact.

## The rules are old; the reaction to AI was not

| Date | Change |
|---|---|
| **2024-12-04** | The AI section is added to `CONTRIBUTING.md`, in a commit titled *"Meta: Add policy on AI/LLM usage for changes and reviews"*[^lb-commit-2024] |
| **2026-04-05** | A clause is added: *"Do not submit PRs with descriptions entirely generated by AI. Such PR descriptions are overly verbose and **do not demonstrate that the human submitter understands the proposed changes**"*[^lb-commit-prdesc] |
| **2026-06-05** | Public pull requests end. `CONTRIBUTING.md` is gutted, `Documentation/CodePolicy.md` is created, and the AI section moves there[^lb-commit-restructure] |

**The 2026-04-05 clause is gone from the current text, because the thing it governed is gone.** With no
outside pull requests there are no outside pull request descriptions, and the surviving sentence was
reworded from *"interact with PRs"* to *"participate in project discussion"*. The policy did not soften;
its subject disappeared.

## Why the channel closed, in the project's own words

The announcement is the most direct statement in this bundle that AI broke a social mechanism rather
than produced bad code:

> For decades, code contributions have been how open source projects learned who to trust. People would
> show up, do the work, take responsibility for their changes, and stick around.
>
> **AI tools have changed the economics of this very quickly. We use them ourselves every day, but a
> pull request no longer tells us as much as it used to about the person submitting it.** A substantial
> patch used to imply substantial effort, and that effort was a reasonable proxy for good faith. **That
> assumption no longer holds.**[^lb-post-closing]

The security argument follows from the product, not from provenance: *"A browser runs untrusted input
from the entire internet on the user's machine, and one well-disguised vulnerability is all an attacker
needs. We have already seen patient, well-resourced campaigns in open source to earn maintainer trust
and abuse it. What has changed is how much faster and cheaper it has become to produce work that looks
like a serious contribution."*[^lb-post-closing]

**And the conclusion is explicitly not about detection:**

> **Whether code was typed by hand is beside the point.** What matters is who is responsible for it
> once it enters the browser.[^lb-post-closing]

Every other record here tries to keep a contribution channel open while managing what arrives through
it — by disclosure, by trailers, by canaries, by review. Ladybird closed the channel. It also closed the
escape routes: *"There will not be a separate process for submitting patches by other means. We do not
want to create a shadow contribution system through issues, comments, email, or forks."*[^lb-post-closing]

## It happened, and it is measurable

- **93 pull requests were closed on 2026-06-05**, of which 15 were merged — against 24, 28, 12 and 17
  closed on the surrounding working days. The announcement said all open pull requests would be closed,
  and roughly 78 were closed unmerged that day.
- **1,575 pull requests have been created since.** Of the 50 most recent, every one comes from ten
  accounts; a sample of the 100 most recent merged ones has eleven distinct authors. The channel is open
  only to the people who run the project.
- Bug reports, reductions, testing, standards and design discussion, security reports and technical
  feedback are all still invited.[^lb-contributing] Security reports have their own route, and the
  security policy — which predates all of this — never mentions AI.[^lb-security]

## The same project ported its JavaScript engine with AI

Three months before closing contributions, Ladybird's founder published an account of using AI on the
codebase:[^lb-post-rust]

> **I used Claude Code and Codex for the translation. This was human-directed, not autonomous code
> generation.** I decided what to port, in what order, and what the Rust code should look like. It was
> hundreds of small prompts, steering the agents where things needed to go. After the initial
> translation, I ran multiple passes of **adversarial review, asking different models to analyze the code
> for mistakes and bad patterns.**

The stated result is about 25,000 lines of Rust in roughly two weeks, work estimated at *"multiple
months to do by hand"*, with byte-identical bytecode against the C++ pipeline and zero regressions
across 52,898 test262 tests and 12,461 project tests. **Those are the project's own figures**, verified
here only as being what the post says.

**So the position is coherent rather than contradictory.** AI is welcome where a responsible maintainer
directs it and answers for the result; what is refused is AI-shaped evidence of trustworthiness from
someone the project does not know. [Elixir](elixir.md) reaches a related conclusion — *"we often find
the point of view of the human behind the agent more valuable"* — but keeps its channel open.
The adversarial-review technique is the same one [Elixir](elixir.md) asks contributors to apply.

## Where the policy now lives, and who it is for

`CodePolicy.md` opens by saying it is *"primarily intended for project maintainers and people studying
local Ladybird development"*.[^lb-code-policy] `CONTRIBUTING.md` does not link it; only the documentation
index does.[^lb-docs-index] **This is the only record here whose AI rules address the people who write
the code rather than the people who might submit it** — which follows from there being no submitters.

The repository carries none of the eighteen agent-instruction filenames this bundle surveys for
(checked 2026-09-16), so nothing in the tree instructs a tool directly.

## What a contributor must do

**You cannot contribute code.** Do not open a pull request, and do not route a patch through an issue,
a comment, an email or a fork — the project has said it will not treat those as a review queue. File
bug reports, reductions and security reports; join the standards and design discussion. If you use AI
in any of that, hold its output to the standard a human's would meet, and never post a summary you have
not understood. If you are a maintainer, the same rules govern the code you write.

## Re-verification notes

**Check the channel before the policy.** `CONTRIBUTING.md`'s first paragraph is the load-bearing
sentence; if it reopens, this record changes shape entirely. A cheap check is the authorship of recent
pull requests — a non-maintainer author would mean the rule moved.

**Read the files, not a code search.** GitHub's code search returned zero hits for a term that is
present in a repository checked the same day, so absence in search results proves nothing here. The AI
section lives in `Documentation/CodePolicy.md`, which is not where a contributor would look; the
documentation index is the only path to it.

Watch whether the AI section changes now that it addresses maintainers, and whether any trailer
convention appears — the project currently asks for none.
