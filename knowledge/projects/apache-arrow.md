**Stance: permitted, with a standing threat of closure.** The *AI-generated code* section of the developer
documentation opens by accepting the tools and then names the cost:

> Thoughtful use of these tools can be beneficial, but AI-generated PRs can sometimes lead to undesirable
> additional maintainer burden. PRs that appear to be fully generated by AI with little to no engagement from
> the author may be closed without further review.[^ar-overview]

The reason given is not licensing and not quality but **what review is for**: *"code review is intended to be
a collaborative learning experience that benefits both submitter and reviewer"*, and when a pull request
looks generated, *"reviewers with access to AI tools could more efficiently generate the code directly"*,
so the submitter's time is better spent *"researching and reporting on the issue"*.[^ar-overview]

## Where it lives and when it arrived

It is a section of `docs/source/developers/overview.rst`, added on 2026-01-28.[^ar-pr-48952] It is surfaced
by a heading in `CONTRIBUTING.md` — *"Are you using AI coding tools?"* — by a paragraph in the README, and
by a note in the developer guide's index.[^ar-contributing][^ar-readme] The pointers in `CONTRIBUTING.md` and
the README arrived later, on 2026-05-27,[^ar-pr-49277] so for four months the policy was reachable only
from the documentation.

## Seven recommendations, one added later

Beyond the closure threat the section says *"We are not opposed to the use of AI tools in generating PRs, but
recommend the following"*, then lists seven points.[^ar-overview] Four are ordinary: match the codebase's
style, explain what you verified, break large changes up, and watch for verbose comments and needless tests.
Three bear on this bundle:

- **Ownership:** *"Only submit a PR if you are able to debug and own the changes yourself"*.
- **Disclosure, in prose:** *"Be upfront about AI usage and summarise what was AI-generated"*. The section
  names no trailer, no label and no field. See [Assisted-by trailer](../mechanisms/assisted-by-trailer.md).
- **Agents:** *"AI agents should never tag or ping maintainers"*, a recommendation like the rest, added on 2026-05-27 as a one-line
  addition to the list.[^ar-pr-49277]

**Licensing is delegated.** *"PR authors are also responsible for disclosing any copyrighted materials in
submitted contributions"*, and the section links the ASF's guidance *"for further information on licensing
considerations"*.[^ar-overview] The link is for licensing only. It does not mention the guidance's
`Generated-by` token, which [the ASF's own record](../foundations/apache-software-foundation.md) describes.[^ar-asf]

## Prose reserved to the human

The same 2026-05-27 change added a note to the communication guide:

> Using AI tools to help with phrasing or grammar is absolutely fine. However, we'd love to hear from *you*
> rather than your AI assistant - please don't use AI to generate questions or comments on your
> behalf.[^ar-communication]

**The pull request's title and its text differ.** It is titled *"Update docs to specify disclosure of AI on
mailing list messages"*, and the note it adds restricts AI-written questions and comments and asks for no
disclosure; the diff contains no disclosure requirement.[^ar-pr-49277] The rule in force is the one in the
text. See [prose reserved to humans](../mechanisms/prose-reserved-to-humans.md).

## It runs an AI reviewer, briefed for brevity

`.github/copilot-instructions.md` opens *"You are a pragmatic senior developer"* and tells the bot to be
concise, report only high-impact problems, skip the obvious and trivialities, comment once per pattern, and
tell first-time contributors to *"check and address all review comments in this PR"*.[^ar-copilot] It was last
changed on 2026-06-14, in a pull request about *"preliminary reviews"*.[^ar-pr-50117] The brief says nothing
about the AI policy and nothing about the project's own rule on agents. The nearest comparison is
[Valkey](valkey.md)'s review bot, which is briefed on its governance file; this one is briefed on tone.

## Practice in the main repository: trailers, but never the ASF's

A partial clone of `main` on 2026-10-03 (`--shallow-since=2025-10-01`, 1,405 commits) counts **26 commits
with an AI trailer: 20 `Co-authored-by: Copilot Autofix powered by AI`, 4 `Co-authored-by: Copilot`, and 2
naming Claude** — the other trailers name people and a few bots. **None uses `Generated-by:` or
`Assisted-by:`**, the forms the ASF guidance asks for. By month the first is in 2026-02, after the policy
landed, and the count peaks at 8 in 2026-07 and 8 in 2026-09. The probe was checked: a planted string absent
from every commit returned zero.

## arrow-adbc: a separate repository that says nothing

`apache/arrow-adbc` is a separate repository in the same GitHub organisation. **Neither its contributing
guide[^ar-adbc-contributing] nor its README[^ar-adbc-readme] mentions AI policy or links Arrow's, and
neither do its development pages or its issue and pull request templates** — 94 further documentation,
template and workflow files were scanned for *AI*, *LLM*, *generative*, *Generated-by*, *Assisted-by*, *Copilot*, *Claude* and *agent*; the
hits were `gpg-agent`, a Spice.ai test step and product wording. Whether Arrow's section is meant to govern
it is **not stated anywhere I found**.

Its commit history, though, carries a much larger share of AI trailers than the main repository's: 51 of 809 commits (6.3 percent) against 26 of 1,405 (1.9 percent). A partial clone with the same window
counts **51 of 809 commits with an AI trailer**, in four forms:

| Form | Commits |
|---|---:|
| `Assisted-by:` | 25 |
| `Co-authored-by:` naming Claude | 17 |
| `Generated-by:` | 8 |
| `Co-authored-by: Copilot` | 1 |

The model strings as written include GPT and Claude versions, and the earliest trailer, a Claude credit, is
dated 2025-10-16 — before Arrow's policy existed. **The `Generated-by` and `Assisted-by` commits all begin on
2026-06-14, five months after the policy, and 32 of the 33 carry one author name.** Nothing in either
repository asks for them. They match the ASF's `Generated-by` token, and the main repository never uses it,
so this reads as one committer applying the ASF's default in a repository whose own documents are silent,
and not as a project rule. That is an inference from the pattern; no one stated it.

## What a contributor must do

**In the main repository:** use AI tools if you will own and understand every line, say so in the pull
request description, write your own questions and comments, do not let an agent tag a maintainer, and expect
a pull request that looks fully generated to be closed unread. **In arrow-adbc:** nothing is written, so
follow the main repository's section as the nearest statement, and note that its committers do use the ASF's
trailers.
