were read: `CONTRIBUTING.md`,[^pgd-contributing] the README,[^pgd-readme] `CODE_OF_CONDUCT.md`,
`CHANGELOG.md`, the eleven Markdown files under `docs/` and `docker/`, and the three issue-template

*Copilot*, *Claude*, *Cursor*, *ChatGPT*, *Codex* and *agent*. **There were no matches**, while a
control search of DuckDB's `CONTRIBUTING.md` found two. The survey tool found no agent-instruction
file, and the `duckdb` organisation has no `.github` repository of default files.

pg_duckdb is a Postgres extension that embeds DuckDB. It lives in the `duckdb` GitHub organisation,
is MIT-licensed, and its README says it was *"Built in collaboration with"* Hydra and
MotherDuck.[^pgd-readme]

## The guide is a copy taken before the rule existed

The pull request that added the guide, merged 2024-08-07, says so: *"I already trimmed CONTRIBUTING
down from duckdb"*.[^pgd-pr-90] The two guides still share 67 identical lines, including the size
rule and the reservation of discretion, word for word:

> We reserve full and final discretion over whether or not we will merge a pull request. Adhering to
> these guidelines is not a complete guarantee that your pull request will be merged.[^pgd-contributing]

DuckDB's guide gained a *Generative AI Policy* section on 2025-06-11,[^pgd-duckdb-pr-17882] which
opens *"Please do not submit pull requests generated by AI (LLMs)."*[^pgd-duckdb-contributing]
**pg_duckdb's copy was last edited on 2025-03-05,**[^pgd-contributing-history] three months before,
so it cannot contain the section DuckDB added. Nothing in either
file says that DuckDB's rule, or its later `AI_POLICY.md`, covers the organisation's other
repositories. See [DuckDB](duckdb.md), where the same question arose in another extension repository,
and [policy by copying](../mechanisms/policy-by-copying.md) for copies that miss later changes upstream.

## Practice: disclosure in prose, no trailers

A partial clone of `main` on 2026-10-31 contains 631 commits, 53 of them since 2025-10-01; the GitHub
API returns the same 53 for that window. **No commit in the whole history carries a trailer crediting
an AI tool.** Disclosure appears instead in prose, three times, with no rule asking for any of it:

- **A commit message, 2024-10-24.** *"Settings docs were created with lots of help from
  AI"*[^pgd-commit-361] — from an account with collaborator access, eight months before DuckDB's rule.
- **A pull request description, merged 2025-09-03.** *"I'm having Claude test all
  examples"*,[^pgd-pr-826] from an account with collaborator access.
- **A pull request description with its own heading, 2026-10-26.** The pull request that upgrades the
  extension to DuckDB 2.0 has an *AI Disclosure* section: *"Code is generated by AI and all reviewed
  by human. PR description is written by human."*[^pgd-pr-1103] It was still open on 2026-10-31.
  DuckDB's guide would bar that pull request; pg_duckdb's says nothing about it.

The repository also uses GitHub's Copilot review bot: it reviewed 6 of the 85 pull requests opened
since 2025-10-01, all six opened by one account. That is a reviewing tool, not authorship, and no
file mentions it.

**A missing trailer is not evidence of absence.** Nothing asks for one, and the three disclosures
above show contributors who used AI and wrote no trailer.

## What a contributor must do

**Nothing in writing binds you on AI.** Follow the copied guide: discuss intended changes with the core team, keep
pull requests small, run `make format`, and do not open draft pull requests. Contributors here have
disclosed AI use in the description, which is the form this repository has seen; none is required.
DuckDB's own prohibition is not stated to apply here.
